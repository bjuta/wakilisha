## Purpose

Audio must not be a CMS form with Audio fields. It is a governed editorial workstation whose primary coordinate system is time.

The Admin Studio convergence rule remains: different verticals keep purpose-built tools while sharing the same WAKILISHA objects, permissions, lifecycle, lineage, review semantics, and reusable interaction primitives.

## Product model

The Audio workbench is optimized for:

**listen -> inspect -> annotate -> discuss -> replace master -> verify -> approve -> publish**

It is deliberately not a DAW. WAKILISHA does not perform destructive waveform editing, EQ, compression, fades, multitrack mixing, or mastering.

## Audio-specific tools

Audio needs capabilities that Articles and Playlists do not:

- full-length playback transport
- precise playhead and seek controls
- canonical waveform
- time-point and time-range selection
- chapter markers on the same time axis
- rich comments anchored to an exact point/range
- comment markers that jump playback to the anchor
- exact submitted-master review
- codec / sample rate / channel / bitrate / duration facts
- master / transcript / delivery / waveform Media identity

## Reusable editorial primitives

These are cross-vertical concepts:

- `EditorialWorkflowRail`
  - groups work by semantic phase instead of page-specific tabs
- `EditorialCommentEditor`
  - lightweight rich text comment surface
  - TipTap-backed, no raw stored HTML rendering
- `MediaTransport`
  - play/pause, seek, speed, current time, duration
- `MediaTimeline`
  - waveform, playhead, point/range selection, markers
- anchored review thread semantics
  - immutable version target
  - anchor
  - rich comments/replies
  - open/resolved status

Future anchor mappings:

- Article: `document`, `field`, `text_range`
- Audio/Video: `time_point`, `time_range`
- Playlist: `sequence_item`
- Image/Artwork: `spatial_region`
- Chart: `entry`
- Registry record: `field`

The UI contract is generic. Database foreign keys remain domain-specific until WAKILISHA has a real universal Resource-version authority.

## Audio review authority

Audio review threads target `audio.publication_versions.id`.

New thread creation must target `editorial.audio_publication_resources.current_submitted_version_id`, and that version must be `version_kind='submitted'`.

The anchor is validated against the exact submitted version's frozen `audio_delivery_variant_id` Media duration. A comment cannot point beyond the immutable submitted master.

Thread anchors:

- `time_point`
  - `anchor_start_seconds`
  - `anchor_end_seconds = null`
- `time_range`
  - `anchor_start_seconds`
  - `anchor_end_seconds > anchor_start_seconds`

Threads are open/resolved. Comments preserve rich HTML and plain text. All reads/writes use existing `editorial.current_user_can_participate_audio_review(resource_id)` authority.

This does not replace `audio.publication_review_events`. Lifecycle events remain the immutable transition record; threads are editorial discussion attached to the exact version being reviewed.

## Media authority

The workbench reuses canonical Media processing.

Existing selected derivatives provide:

- `audio_delivery`
- `audio_preview`
- `waveform_data`

The waveform JSON is already generated by the Media processor as:

- version
- duration_seconds
- sample_rate
- channels
- peak_count
- peaks

Technical facts come from the derivative file object's `technical_metadata.source_probe`:

- duration_seconds
- format_name
- format_bit_rate
- codec_name
- sample_rate
- channels
- stream bit_rate

No client-side waveform analysis or duplicate Media metadata store is introduced.

## Audio collection

The Audio collection uses one mode composer:

- New Show
- New Season
- New Recording

It does not present three independent creation cards.

The record browser provides search plus lifecycle filters and keeps episode hierarchy visible in each row.

## Audio detail navigation

The detail workbench uses one shared record header plus a grouped workflow rail:

- **COMPOSE**
  - Details
  - Sound & Chapters
- **PREPARE**
  - Credits & Citations
- **WORKFLOW**
  - Review
- **RECORD**
  - History

Versions and Podcast Identity remain persistent record context.

## Review workspace

Review is no longer a single note textarea.

A reviewer gets:

1. exact submitted version identity
2. exact submitted delivery audio
3. transport controls
4. canonical waveform
5. chapter markers
6. existing comment markers
7. drag-to-select time ranges
8. click-to-anchor time points
9. rich comment composer
10. rich thread/reply rail
11. resolve/reopen controls
12. technical facts for the submitted master
13. lifecycle decision note kept separate from anchored editorial feedback
