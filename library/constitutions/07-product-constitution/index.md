# The Product Constitution

## A WAKILISHA page is a step in an Inquiry

A WAKILISHA page is not a destination.

It is a step in an Inquiry.

This sentence should change how the product is built.

Most digital products teach pages to behave like endpoints. You search, you land, you consume, you leave. The page answers one immediate question and then the responsibility ends.

WAKILISHA needs a different pattern.

A user should arrive with one question and leave with more context, clearer relationships, and a better next question.

That is how the product becomes more than an archive.

It becomes a path.

## The minimum job of a public page

Every serious public page should eventually answer seven questions.

What is this?

Why does it matter?

What question does it help answer?

What evidence supports that answer?

What relationships does it reveal?

Where should the user go next?

What remains unknown?

These questions do not need to appear as literal headings on every surface. But the page should carry their logic.

If a page cannot answer them, it is not yet a WAKILISHA page. It is a data page wearing WAKILISHA clothes.

## Product before polish

A polished page can still be shallow.

Good spacing, strong type, sharp cards, and clean motion matter. But polish should not arrive before purpose. The product should first decide what cultural work the surface is doing.

A track page may need playback, but playback is not the whole page.

An artist page may need a hero image, but image is not the whole page.

A release page may need cover art, but cover art is not the whole page.

A chart page may need a ranked list, but ranking is not the whole page.

A Library page may need a clean reading view, but reading view is not the whole page.

The product question is always deeper.

What understanding does this surface create?

## The Question Spine

The Question Spine is the product pattern that turns the constitution into interface.

It has six parts.

Primary question.

Short answer.

Evidence on this page.

Relationships revealed.

Next questions.

Open questions.

The Question Spine should begin as a module and become a product habit. It should not force every page into the same layout. It should give every page the same intellectual structure.

On an artist page, the Question Spine may live near the top and connect to discography, chart history, collaborations, and related artists.

On a track page, it may sit beside playback, release context, chart appearances, and credits.

On a chart page, it may frame the edition: what does this ranking help us understand about attention right now?

On an article, it may become a reading path that names the argument and the next questions.

On a Library document, it may explain the principle and the decisions it governs.

The Question Spine is not a decoration. It is the page’s reason for being.

## Relationship paths

Recommendation is not enough.

Many products say: you may also like this.

WAKILISHA should say: this is connected, and here is why the connection matters.

Relationship paths should be labelled.

Same producer.

Shared chart moment.

Common scene.

Language relationship.

Label relationship.

Influence path.

Diaspora route.

Historical echo.

Argument in common.

A relationship path should make the reader smarter before they click.

## Product objects

The main public objects of WAKILISHA are artists, tracks, releases, labels, genres, charts, articles, Library documents, comments, profiles, and Inquiries.

But the deepest product object is the question.

A track matters because of the question it helps answer.

An artist page matters because of the questions it gathers.

A chart matters because of the question it asks about attention and movement.

A comment matters if it improves the question, the evidence, or the relationship map.

An AI suggestion matters only if it helps the Inquiry become clearer.

This hierarchy should guide product design.

## Product restraint

WAKILISHA should not build every feature it can imagine.

A feature belongs when it helps the institution understand, remember, explain, connect, or invite contribution.

A feature does not belong because other products have it.

Comments belong if they improve Inquiry.

Profiles belong if they help people contribute, save, follow, and build memory around cultural work.

Share sheets belong if they help cultural artifacts travel with context.

Notifications belong if they call people back to meaningful changes, not empty nudges.

AI belongs if it helps organize and deepen the work, not if it makes WAKILISHA sound clever while knowing less.

## Product implications by surface

Artist pages should become cultural introduction surfaces. They should answer who the person is, but also what the artist helps us understand.

Track pages should become moment surfaces. They should explain why the record matters, what it connects to, and where it sits in sound, release, chart, and memory.

Release pages should become intention surfaces. They should show what the project gathers, what changed around it, and how it relates to the artist’s larger path.

Label pages should become industry relationship surfaces. They should make invisible infrastructure visible.

Genre pages should become argument surfaces. They should show overlap, boundary, scene, and movement.

Chart pages should become attention surfaces. They should explain rank, movement, durability, entry, exit, and method.

Article pages should become authored answer surfaces. They should connect argument to evidence and related artifacts.

Library pages should become constitutional surfaces. They should show why a principle exists and how it governs future decisions.

## Editorial implications

Product and editorial should not be separate kingdoms.

Every page has copy. Every card has a claim. Every label teaches the reader what to notice. Every empty state tells a story about what is missing. Every related module shapes understanding.

Editors should help shape product language.

Product builders should understand editorial purpose.

AI systems should inherit both boundaries.

The institution gets stronger when the product thinks editorially and editorial work understands product behavior.

## Community implications

Product should design for contribution, not only consumption.

A reader who knows something should have a path to contribute it.

A user who sees a mistake should have a path to correct it.

A listener who remembers a context should have a path to share it.

A researcher who sees a relationship should have a path to propose it.

But contribution needs structure. WAKILISHA should not ask for everything. It should ask for useful things.

What context are we missing?

What relationship should we check?

What memory belongs here?

What question should come next?

## AI implications

AI should be built into the product as an assistant to the constitution, not a shortcut around it.

A future AI feature should know the Question Spine.

It should know the difference between known, inferred, uncertain, and missing.

It should know which Library principles apply to a surface.

It should be able to warn when a page is padded, generic, or disconnected.

It should help make WAKILISHA more itself.

If it makes WAKILISHA sound like everyone else, it has failed.

## Decision tests

What question does this feature help answer?

Does the feature deepen understanding or only increase activity?

Does it reveal relationships?

Does it preserve memory?

Does it invite useful contribution?

Does it respect uncertainty?

Would the feature still matter if it were not fashionable?

## Failure modes

WAKILISHA is drifting when product features imitate competitors without answering WAKILISHA questions.

It is drifting when pages answer one thing and stop.

It is drifting when related content has no relationship labels.

It is drifting when UI polish hides weak cultural work.

It is drifting when AI becomes a writing shortcut instead of an inquiry assistant.

It is drifting when engagement becomes the goal.

## Closing note

The product should teach people how to move through culture with care.

Every page should say: here is what we know, here is why it matters, here is what it touches, and here is where your curiosity can go next.
