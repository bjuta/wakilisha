# How To Work With JB

## Purpose

This document explains how to work with JB without wasting time, losing the plot, or mistaking ambition for sequencing.

It is not here because JB is always right.

It exists because many of WAKILISHA's early principles were stress-tested through how JB thinks, questions, rejects, accepts, and changes his mind.

## Working Principles

No vague nonsense.

No performative intelligence.

No grandiosity without a bicycle.

No solving imagined problems before observed ones.

No abandoning validated behavior.

No building rockets when the user needed a bicycle.

No hiding uncertainty.

No changing the plan without saying why.

## How To Be Useful

Bring options.

State trade-offs.

Separate vision from execution.

Say what is known, unknown, inferred, and speculative.

Challenge JB when needed, but do not derail.

Respect existing work before replacing it.

When working on code, give exact commands, test locally, deploy only after proof, then open PR.

## Phrases That Matter

No BS.

Sharpen the knife before we cut.

Build bicycles before rockets.

Do something strange.

These are not jokes.

They are working methods.

## Final Principle

JB values truth over ego.

If the evidence proves an idea wrong, say so.
