# The Community Constitution

## Community exists to improve understanding

Community exists to improve understanding, not to manufacture noise.

This sentence should govern every future comment feature, profile feature, contribution flow, notification, prompt, and moderation decision.

WAKILISHA should not build community because every media product eventually says it needs engagement. It should build community because cultural memory is not held by institutions alone.

People remember things archives miss.

They remember where a song first moved.

They remember the club, the school, the estate, the bus, the church, the campus, the radio show, the DJ, the producer tag, the rumor, the lyric meaning, the joke, the argument, and the moment a record became more than a file.

That memory matters.

But memory needs shape if it is going to help the institution.

## Contribution, not noise

A comment can do cultural work.

It can correct a fact.

It can add a source.

It can bring a memory.

It can explain a local meaning.

It can translate a phrase.

It can challenge a lazy interpretation.

It can name a missing artist.

It can open a better question.

But a comment can also make the work worse. It can harass, flatten, distract, misinform, provoke, or turn a serious Inquiry into a shouting room.

The difference is not whether people agree.

The difference is whether the contribution helps understanding.

## The shape of a useful thread

A useful WAKILISHA thread should make it easy to see different kinds of contribution.

Context.

Correction.

Memory.

Source lead.

Question.

Disagreement.

Translation.

Relationship suggestion.

These categories do not need to become heavy labels everywhere, but the product should know they exist.

A nested thread can be valuable when it lets a correction, memory, or disagreement develop properly. Nesting should not exist only because another platform has it. It should exist because cultural dialogue often needs reply, clarification, and return.

## Profiles and identity

User profiles should not turn WAKILISHA into a social network before the product needs one.

Identity matters because contribution needs accountability and memory.

A person who leaves useful corrections over time should be recognizable.

A person who builds good collections should have a place for them.

A person who follows an Inquiry should be able to return.

A person who contributes local knowledge should not disappear into a flat comment count.

But WAKILISHA should avoid building status games too early.

The goal is not to make people perform expertise. The goal is to help them contribute to understanding.

## Moderation

Moderation should protect the conditions for understanding.

It should remove harassment, identity attacks, targeted abuse, deliberate misinformation, spam, and empty provocation.

It should not remove disagreement because disagreement is uncomfortable.

A truthful institution needs room for correction and argument. Some cultural questions are contested because culture itself is contested. WAKILISHA should not pretend that every thread has a neat answer.

The moderation question is not: does this make everyone comfortable?

The question is: can this contribution help the Inquiry without harming the people involved?

## Product implications

Comment prompts should be specific.

Weak prompt: what do you think?

Better prompt: what context are we missing?

Better prompt: where did this song first move?

Better prompt: what should we correct?

Better prompt: who else belongs in this relationship?

Better prompt: what question should this open next?

The prompt shapes the thread.

The product should also preserve useful contribution. A great correction should not disappear under noise. A strong memory should be linkable. A source lead should be reviewable. A relationship suggestion should be able to enter an editorial or research queue.

Community should feed Inquiry carefully.

## Editorial implications

Editors should treat community as possible evidence, not automatic truth.

A user memory may become a lead. A correction may become a fix. A disagreement may become a new article. A thread may reveal a question the institution had not seen.

But editorial judgment remains necessary.

The institution should thank contributors, verify claims, and preserve the difference between memory, evidence, and interpretation.

## AI implications

AI may help moderate, summarize, group, and route contributions.

It can identify likely corrections, repeated questions, abusive patterns, and useful source leads.

But moderation cannot be fully handed to AI. Cultural language is too contextual. Slang, irony, code-switching, local references, and reclaimed language can be misread.

AI can assist community care. It cannot replace human judgment.

It should also be used to surface useful contribution, not only to suppress bad behavior.

## Decision tests

Does this community feature improve understanding?

What kind of contribution does it invite?

Can useful contributions be found later?

Does the feature protect people from harm?

Does it allow disagreement without rewarding abuse?

Can community input improve pages, Inquiries, and relationships?

Does it create memory, or only activity?

## Failure modes

WAKILISHA is drifting when community is measured only by volume.

It is drifting when comment prompts are vague.

It is drifting when useful contributions vanish under noise.

It is drifting when disagreement is confused with harm.

It is drifting when abuse is tolerated as engagement.

It is drifting when AI moderates culture without cultural judgment.

It is drifting when profiles become status theatre instead of contribution memory.

## Closing note

Community is not the crowd outside the institution.

It is one of the ways the institution listens.

But listening requires form, care, and memory.

WAKILISHA should build community so that better questions, better corrections, better memories, and better relationships can survive.
