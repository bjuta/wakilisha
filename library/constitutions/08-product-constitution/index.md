# Product Constitution

## Product Principle

Build bicycles before rockets.

The long-term vision may be ambitious.

The next step should be modest.

Always build the smallest thing that teaches us something true.

## Before Building

Every product proposal must answer:

What problem are we solving?

What evidence shows this problem exists today?

What is the smallest useful version?

How will we know we were right?

If this feature disappeared tomorrow, would WAKILISHA still fulfill its mission?

## Evidence Before Features

Do not build infrastructure for imagined behavior.

Let behavior earn architecture.

If people do not contribute yet, do not build a complex reputation system.

If editors are not repeating a task yet, do not automate it.

## Final Principle

Every feature should make WAKILISHA clearer, more trustworthy, more connected, or more useful to an Inquiry.
